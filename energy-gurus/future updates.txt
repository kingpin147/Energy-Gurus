# Updated Implementation Plan

## Goal Description
Implement the remaining enhancements identified in the **future updates.txt** audit for the EnergyGurus platform, incorporating the latest user decisions:
- Replace hard‑coded monitoring data with dynamic DB‑driven data.
- Generate report CSVs server‑side via a new `/api/reports` endpoint.
- Remove all QR‑code functionality.
- Wire up quick‑action buttons to the specified routes.
- Migrate file uploads from UploadThing to Cloudflare R2.
- Perform cleanup and UI polish tasks.

## User Review
All decisions have been confirmed by the user; no further review is required.

## Proposed Changes
---
### 1. Monitoring Page – Dynamic Data
- **Database**: Create a new table `monitoring_stats` with columns:
  - `id` (PK)
  - `total_power_flow` (numeric, kW)
  - `grid_export` (numeric, kW)
  - `self_consumption` (numeric, %)
  - `inverter_health` (JSON – status, temperature, efficiency per inverter)
  - `alerts` (JSON array of alert objects with type, message, timestamp)
  - `updated_at` (timestamp)
- **Helper**: Add `src/lib/monitoring.ts` exposing `getMonitoringStats()` that queries this table and returns data for the UI.
- **Page Update**: Modify `src/app/[locale]/dashboard/monitoring/page.tsx` to call `getMonitoringStats()` and render the returned values instead of the static numbers.
- **Security**: Add an admin‑only role guard to the monitoring page.

### 2. Reports – Server‑Side CSV Generation
- **API Route**: Implement `src/app/api/reports/route.ts` that accepts a `type` query (e.g., `users`, `inquiries`, `reviews`) and streams a CSV generated on the fly.
- **Utility**: Add `src/lib/reports.ts` with `generateReportCSV(type)` that pulls data from the corresponding DB tables and returns a CSV stream.
- **Page Update**: Update `src/app/[locale]/dashboard/reports/page.tsx` to replace static download buttons with `DownloadButton` components that call the new `/api/reports?type=…` endpoint.
- **Security**: Protect the reports page with an admin role guard.

### 3. QR‑Code Functionality
- **Removal**: Delete all QR‑code related components, pages, and routes. No re‑addition.

### 4. Quick‑Action Buttons on Main Dashboard
Replace placeholder `<button>` elements with functional navigation links:
- **Reply to Inquiries** → `/dashboard/inbox`
- **Update Portfolio** → `/dashboard/epc#projects`
- **Add New Product** → `/dashboard/brand#products`
- **Generate QR Codes** – removed (no target).

### 5. Upload Migration to Cloudflare R2
- **R2 Wrapper**: Create `src/lib/cloudflareR2.ts` that provides `uploadFile(buffer, path)` using the Cloudflare R2 SDK.
- **Deprecate UploadThing**: Update `src/lib/uploadthing.ts` to delegate to the R2 wrapper and mark the original functions as deprecated.
- **Migration Script**: Add `src/scripts/migrate-uploads.ts` to copy existing files from the UploadThing bucket to the Cloudflare R2 bucket.
- **UI Update**: Adjust any UI components (`UploadButton`, `UploadDropzone`) to use the new R2 upload endpoint.

### 6. Cleanup & Consolidation
- **Delete** `src/app/[locale]/dashboard/podcasts/page.tsx` (superseded by `content/page.tsx`).
- **Ensure** `src/app/[locale]/dashboard/content/page.tsx` is linked in the admin sidebar.
- **Sidebar Updates**: Add missing links for Monitoring, Reports, Seed, and Content pages (admin‑only) in `Sidebar.tsx`.
- **Remove Debug Logs**: Strip all `console.log` statements from production files (e.g., `inbox/page.tsx`).
- **Locale Selector**: Implement `onChange` in `settings/page.tsx` that calls `router.replace` with the selected locale.
- **Replace Hard‑Coded Stats**: On the main dashboard, substitute any static numbers (e.g., total power flow, brand views) with live queries using existing DB helpers.
- **Run Lint & Format** to ensure no stray placeholders remain.
